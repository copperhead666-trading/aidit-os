# delegation (AHMAD core skill)

Writes task packets, selects implementer by boundary/availability, sets acceptance criteria,
routes to review.

How this org actually runs it:
- Pick the implementer by role boundary, not familiarity. HATTA implements; SJAHRIR does
  heavy-context research; thin specialists do exactly their boundary, nothing more.
- State explicit acceptance criteria in the packet — "works" is not "meets spec". A reviewer
  (GIBRAN) will judge the artifact against these, so make them checkable.
- After HATTA delivers a material change, route to GIBRAN for an independent verdict. Never
  self-approve delegated work.
- There is no task-packet-standard.md in this repo; a packet is AHMAD's structured plain-text
  prompt handed to the chosen harness/CLI. Keep it minimal-sufficient.
- Include a "Loaded skills" section (see resolveSkillsForPacket) so the agent's context is
  scoped to what the task actually needs, not the whole skill library.
